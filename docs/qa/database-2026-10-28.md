## 1. Scope

Release 1.0 schema as deployed by Liquibase: 29 tables, 95 indexes, 6 sequences, 33 triggers, 1 function, 1 scheduler job, reference data. Out of scope (later gates): PL/SQL API packages, grants to `JMEDS_API`/`JMEDS_RO`, masked views, ORDS, APEX.

## 2. Test suite

85 utPLSQL tests in 4 suites, deployed by Liquibase from `database/tests/` with `context:dev,test` (never in production). Each suite builds its fixture (one valid, linked row in every table) inside the test transaction; utPLSQL rolls everything back, so no test data remains in the demo database.

| Suite | Tests | Result |
| --- | --- | --- |
| `jm_ut_schema`: conventions | 15 | 15 passed |
| `jm_ut_constraints`: constraints and business rules | 43 | 43 passed |
| `jm_ut_triggers`: triggers | 21 | 21 passed |
| `jm_ut_reference`: reference data and jobs | 6 | 5 passed, 1 disabled (DEF-005) |
| **Total** | **85** | **84 passed, 0 failed, 0 errors, 1 disabled**; run time 11 s |

**Design choices that make the suite hard to fool:**
- **Generic tests read the data dictionary,** so a constraint or table added later is tested automatically. A check constraint too complex to probe generically *must* have its own named test, or `every_check_constraint` fails.
- **Each negative test asserts the specific constraint that fired,** not just "an error". This caught two overlapping rules that a weaker test would have passed.
- **CI fails if 0 tests run,** which guards against the silent-annotation loss in DEF-010.

**Mutation check (do the tests catch real breakage?).** With the temperature range check, the vitals lock guard and the audit-log guard deliberately disabled, **9 tests failed**, exactly the ones covering those protections. All three were then restored (`ENABLED`/`VALIDATED`) and the suite went green again.

## 6. Changes made by this gate

- **Database** (fix forward):
  - `090_audit_triggers.sql`: three guard triggers rewritten (DEF-003); `stripComments:false` on every PL/SQL changeset (DEF-010).
  - `seed-data/020_lookups.sql`: seven new lookup changesets (DEF-004).
  - `database/tests/`: four suites plus fixture, wired into `controller.xml`.
- **QA tooling:**
  - `database/qa/schema_columns.sql` with `.github/scripts/check-schema-vs-design.sh`: design conformance.
  - `database/qa/schema_snapshot.sql`: before/after comparison.
  - `check-changesets.sh` now also requires `stripComments:false` on PL/SQL and `context:dev,test` on tests.
- **CI:**
  - Pull requests now deploy to the demo database (the single dev/test environment, decision D1), then roll back and re-apply the changesets they added.
  - New steps check the schema against JM-DOC-03 and fail when utPLSQL is missing or no tests run.
- **Documents:** JM-DOC-03 v0.2 (DEF-001, -002, -007); this report; defect register.
