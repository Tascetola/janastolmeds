## 1. Scope

- **`database/packages/jm_ctx_api.sql`:**
  - `set_staff`, `set_patient`, `set_system`, `clear`;
  - getters for every context attribute;
  - `has_role`, `require_role`, `require_patient_access`;
  - EXECUTE granted to `JMEDS_API`.
- **Design** (JM-DOC-03 section 6):
  - Every `set_*` clears first, because APEX and ORDS sessions are pooled.
  - Inside APEX, the staff username must equal `APP_USER`.
  - `set_system` only works in a JMEDS session, so the APEX/ORDS connection cannot claim to be a job and skip the role checks.
  - The patient actor is `PATIENT:<account_id>`, never the login ID (an email or phone number would be personal data copied into the audit columns).
- **DEF-008:**
  - `JM_CURRENT_USER` now prefers the JM_CTX actor.
  - All 29 `<TABLE>_BIU` triggers always stamp `CREATED_BY` and `CREATED_ON` on insert, overruling any value the caller supplies.
  - Synthetic data is loaded as `set_system('JM_TEST_DATA')`.
- **CI:** a new step fails the build when any `JM_*_API` package is below 80% line coverage, or has no coverage reported. The step excludes `JM_UT_*` test packages; testing the step's query locally showed they would otherwise match.
